# 版本发布与分发规范 - ActionDock 2.x

- **触发事实源**：以 GitHub Release 作为唯一触发源。本地不手工管理 Git 标签。禁止脱离版本发行在本地手工发布。
- **分发标签隔离**：正式版本使用默认分发标签 `latest`。预发布测试版本使用 `beta` 或 `alpha` 等独立标签。系统严禁测试版本覆盖 `latest` 指针。
- **版本命名规范**：
  - 正式版本：采用语义化版本号，如 `2.8.0` 或 `v2.8.0`。
  - 测试版本：采用预发布版本号，如 `2.8.1-beta.0` 或 `v2.8.1-beta.0`。
- **多包依赖对齐**：发布测试版本时，所有子包与模板互引依赖须对齐版本号。这可避免 npm 回退加载旧版本。
- **发布验证与执行流**：
  - 验证流程：发布前必须通过 `npm test`、`npm run typecheck` 与打包烟雾测试 `npm run test:pack`。
  - 变更提炼与解读：智能体对比上一版本与当前分支的代码改动。重大版本须撰写包含背景、核心能力与迁移说明的解读。微小改动简要说明变动目的。通过 `--overview` 或 `--overview-file` 参数传给发版脚本。脚本自动将解读与 Git 提交明细装配为发布说明。
  - 规范发版提交：更新各包版本后创建提交。提交标题统一为 `chore(release): release <version>`。正文附带包含解读与提交明细的发版说明。
  - 远程发布执行：推送代码至发布分支后创建 GitHub Release。GitHub Actions 监听事件并解析版本类型。系统按依赖拓扑顺序自动化发布。
