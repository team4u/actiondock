# 系统概览与核心概念

ActionDock 是面向 AI 智能体的 Action 与 Skill 开发、测试、构建与分发工具链。

它连接工具创作者与智能体使用者，实现能力的定义、验证、裁剪与多模态分发，建立起工业级确定性的智能体工具底座。

---

## 为什么需要 ActionDock

在代码绝大部分由智能体生成的时代，工具研发的瓶颈不再是手写几行胶水代码，而是工程的确定性、质量自愈与免维护交付：

- 随手编写的临时脚本容易脆断：缺乏规范的输入输出校验与环境隔离，容易因为依赖缺失或配置漂移而运行中断。
- 普通封装库缺乏规程约束：仅把函数接口暴露给大模型，在复杂多步任务中，模型极易产生幻觉、颠倒调用顺序甚至误触破坏性操作。
- 难以跨环境分发与复用：针对特定宿主或平台手写的工具，无法直接跨本地命令行、MCP 服务、远程微服务与便携技能包无缝复用。

ActionDock 践行**「人定规程，智能体写实现」**的全新工程协作范式：人类专家在操作规程中划定业务时序与安全底线，智能体依据强类型契约编写具体实现，并通过纯内存测试沙箱实现闭环自愈。

---

## 三大核心概念

ActionDock 围绕三个相互协同的核心概念构建：

```text
Playbook（操作规程）──── 人定规程（时序约束、分支判断、安全红线）
        │
        ▼
 Action （原子能力）──── 智能体实现（强类型契约、确定性执行、纯内存单测）
        │
        ▼
  Skill （技能资产）──── 自包含交付（面向智能体打包，自动引导环境就绪）
```

- **Action（原子能力）**：
  确定性的原子任务执行单元。每个 Action 负责一项明确的业务能力（如查询 PR、执行数据库操作、处理文件或调用外部服务）。通过强类型接口与输入输出模式（JSON Schema）进行严格约束，确保输入合规与输出确定。
- **Playbook（操作规程）**：
  面向智能体的标准作业规程（SOP）。采用纯 Markdown 编写，沉淀领域专家的作业步骤、前置依赖检查、判断分支与不可逾越的安全红线，防止智能体在复杂流程中脱轨。
- **Skill（智能体技能）**：
  面向智能体的高级自包含交付资产。将原子 Action 与操作规程 Playbook 融为一体，生成包含 `SKILL.md` 的规范技能目录。智能体通过技能管理器安装后，能够自主索引规程并调度底层工具。

## 一份源码，全模态交付

使用 ActionDock 编写的 Action 与 Playbook，只需维护单一源码事实源，即可无缝交付为多种目标形态：

```text
TypeScript 动作源码
       │
       ├── 本地执行   ──> ad run sample.greet
       ├── 协议挂载   ──> ad mcp (STDIO / HTTP 服务，直连 Cursor、Claude Code)
       ├── 智能体技能 ──> ad export skill (导出自包含 Agent Skill)
       ├── 远程微服务 ──> ad serve (高可用 RESTful 微服务)
       └── 独立交付   ──> ad build (自包含 Node.js 运行时目录)
```

- 智能体生态无缝集成：通过标准技能包格式交付，主流智能体客户端开箱即用。
- 协议直连无缝适配：原生支持 Model Context Protocol，本地开发工具一键直连。
- 生产环境高可用部署：支持作为独立的 HTTP 微服务集群部署，或构建为免全局依赖的自包含 Node 目录交付产物。
