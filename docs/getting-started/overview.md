# 系统概览与核心概念

ActionDock 是 Agent 工具的工程化交付链。

把 Agent 写出来的工具代码，变成可测试、可约束、可复现、可交付的生产级软件资产。

---

## 为什么需要 ActionDock

在代码绝大部分由 Agent 生成的时代，生成一段功能函数只需数秒，工具研发的真正瓶颈在于工程确定性、安全边界与免维护交付：

- FastMCP 侧重于简化单个协议服务的编写。
- ActionDock 致力于让团队放心把 Agent 生成的工具代码投入生产环境运行。

单纯暴露裸函数或临时脚本存在明显的生产隐患：

- 随手编写的临时脚本容易脆断：缺乏规范的输入输出校验与环境隔离，容易因为依赖缺失或配置漂移而运行中断。
- 普通封装库缺乏业务规程约束：仅把函数接口暴露给大模型，在复杂多步任务中，模型极易产生幻觉、颠倒调用顺序甚至误触破坏性操作。
- 缺乏确定性的内存测试环境：依赖真实网络与数据库环境的测试缓慢脆弱，无法支持 Agent 在受控沙箱中执行单测并闭环自愈。
- 难以跨环境分发与复用：针对特定协议手写的工具，无法直接跨本地命令行、MCP 服务、远程微服务与便携技能包无缝复用。

ActionDock 践行**人定规程，Agent 写实现**的全新工程协作范式：人类专家在操作规程中划定业务时序与安全底线，Agent 依据强类型契约编写具体实现，并通过纯内存测试沙箱实现闭环自愈。

## 三大核心概念

ActionDock 围绕三个相互协同的核心概念构建：

```text
Playbook 规程 ──── 人定规程（时序约束、分支判断、安全红线）
      │
      ▼
Action 动作   ──── Agent 实现（强类型契约、确定性执行、纯内存单测）
      │
      ▼
Skill 技能资产 ──── 自包含交付（面向智能体打包，自动引导环境就绪）
```

- **原子 Action**：
  确定性的原子任务执行单元。每个 Action 负责一项明确的业务能力（如查询 PR、执行数据库操作、处理文件或调用外部服务）。通过强类型接口与输入输出模式进行严格约束，确保输入合规与输出确定。
- **操作规程 Playbook**：
  面向智能体的标准作业规程。采用纯 Markdown 编写，沉淀领域专家的作业步骤、前置依赖检查、判断分支与不可逾越的安全红线，防止智能体在复杂流程中脱轨。
- **Agent 技能包**：
  面向智能体的高级自包含交付资产。将原子 Action 与操作规程 Playbook 融为一体，生成包含 `SKILL.md` 的规范技能目录。智能体通过技能管理器安装后，能够自主索引规程并调度底层工具。

## 一份源码，多形态交付

使用 ActionDock 编写的 Action 与 Playbook，只需维护单一源码事实源，即可无缝交付为多种目标形态：

```text
TypeScript 动作源码
       │
       ├── 本地执行   ──> ad run sample.greet
       ├── 协议挂载   ──> ad mcp (STDIO / HTTP 服务，直连 Cursor、Claude Code)
       ├── 智能体技能 ──> ad export skill (导出自包含 Agent Skill)
       ├── 远程微服务 ──> ad serve (高可用 RESTful 微服务)
       └── 独立交付   ──> ad build (自包含 Node.js 运行时目录)
```

- 智能体生态无缝集成：通过标准技能包格式交付，主流智能体客户端开箱即用。
- 协议直连无缝适配：原生支持 Model Context Protocol，本地开发工具一键直连。
- 生产环境高可用部署：支持作为独立的 HTTP 微服务集群部署，或构建为免全局依赖的自包含 Node 目录交付产物。
