## 背景

ActionDock 的轻量化目标是让发现工具、查看契约和读取技能说明这些简单操作，不承担执行宿主的资源初始化成本。减法应减少默认负担和重复语义，而不是削弱执行安全，或者再引入一套所谓轻量运行时。

现有重构已经移除了内置 TypeScript 编译链、重复命令、MCP 对业务模式的包装以及文件系统抽象。本次设计建立在这些改动之上，保留 Node.js 24、现有六个包、统一执行服务和已有交付形态。

## 整体设计

继续使用 `ActionDockService`、Host、PackageRuntime、PackageGraph、ActionCatalog 和唯一的 `DefaultExecutionService`。变化只在资源何时创建，不在能力由谁提供。

包对象保留身份、清单、内存注入动作、静态索引及资源选项。包对象创建与包资源打开分离，Host 的同步 `getRuntime()` 和 `listRuntimes()` 不改变返回契约。

```text
发现调用
  → Host 与包图中的已注册包对象
  → 现有静态索引、resolveAction 与可见性判断
  → 返回摘要或契约

状态、配置与历史调用
  → 定位实际需要访问的包
  → 准备所需存储
  → 现有存储与配置解析逻辑

执行调用
  → 现有引用解析与权限校验
  → 已准备或按需准备的包存储、全局配置存储
  → 按需创建唯一 ExecutionService
  → 现有执行链
```

资源边界如下。表中“不开存储”针对旁观模式下的内置实现，不包含调用方已经自行创建的外部实例。

| 操作 | 包存储 | 全局存储 | 执行服务与业务模块 |
| --- | --- | --- | --- |
| `info`、`list`、`describe`、规程发现 | 不打开 | 不打开 | 不创建、不导入 |
| 指定包的状态读写 | 目标包 | 不需要 | 不创建、不导入 |
| 指定包的运行历史查询与清理 | 目标包 | 不需要 | 不创建、不导入 |
| 跨包运行历史查询 | 查询范围内各包 | 不需要 | 不创建、不导入 |
| 包级配置读取 | 目标包 | 按现有配置解析需要打开 | 不创建、不导入 |
| 包级配置写入 | 目标包 | 不需要 | 不创建、不导入 |
| 全局配置管理 | 不需要 | 全局库 | 不创建、不导入 |
| Action 执行 | 持有者预热或按需准备 | 维持现有配置能力 | 目标包创建执行服务，业务模块经既有加载路径导入 |

MCP 和 HTTP 继续使用现有协议适配。远端发现调用不能被本地发现重构替换，本地静态能力也不能绕过远端权限控制。

## 详细设计

### 包对象与资源准备分离

在 `DefaultPackageRuntime` 内部保留两类独立资源槽位，不新增公开运行时类型或通用资源容器：

- 存储槽位：包存储实例及其初始化 Promise。
- 执行槽位：执行服务实例及其初始化 Promise。

全局存储与配置解析器独立缓存，按用途取得，不作为状态查询的必需资源。内部准备方法可采用 `ensureStorage()`、`ensureExecutionService()`、`ensureRuntimeConfig()` 等名称；这些是目标设计，不是现有接口。

构造函数只完成以下操作：

- 确定包目录和规范化配置，沿用现有清单错误处理。
- 创建一次包身份，归一化显式注入的 Action 集合。
- 保存选项、资源提供函数和执行委托。
- 保存或按需创建不打开数据库、不注册加载钩子的默认平台对象。

不得在构造函数访问平台的 `process`、`modules`，也不得调用存储工厂。

存储准备负责打开包存储、等待可选的 `RuntimeStorage.ensureInitialized()`、在持有者模式完成现有恢复，再发布可复用实例。执行准备必须等待存储准备完成，然后取得全局配置存储、进程接口与模块加载器，创建唯一执行服务。

`setActionInvoker()` 在执行服务尚未创建时只保存委托，不能因此触发资源初始化；服务创建后使用最后一次绑定的委托。单包独立使用时继续保留 `INVOCATION_UNSUPPORTED`，不能因为延迟装配绕过跨包调用限制。

`describeAction()` 可以读取内存注入动作和已经存在的执行服务缓存，但不能为了取缓存创建服务或调用动态解析器。磁盘清单与内存动作的字段优先级沿用现有静态索引，不新增第三套合并规则。

### 保留持有者初始化，轻量化旁观路径

本次不改变 `recoverOrphans` 的默认值，不新增 `lite`、`minimal` 或资源开关矩阵。

- 默认持有者工厂继续在返回前获取原有范围的数据目录锁、处理项目事务恢复、打开已注册包所需存储及共享全局存储，并完成运行记录恢复。
- `recoverOrphans: false` 的旁观工厂只准备包元数据、包图和静态发现能力。只有后续状态、配置或历史调用才打开相关存储，不获取执行宿主的排他数据目录锁。
- 持有者工厂预热的是存储，不是执行服务、进程接口或业务模块。
- 公共 `createActionDock()`、`createActionDockHost()` 和 `createPackageRuntime()` 保留默认持有者的初始化失败时机；内部直接构造包对象不等于完成持有者资源准备。

Host 可增加内部的存储准备步骤，调用内置包的内部存储准备方法。该方法只扩展 `HostManagedPackageRuntime` 等内部装配契约，不加入六个公共服务端口。

删除 Host 注册内置包时的即时恢复调用，将恢复收敛到包存储准备中的一个受等待路径。存储打开阶段原有的无会话参数恢复和 Host 会话恢复如果都具有必要语义，应保留原有顺序，但不得在注册和首次调用时重复执行整条恢复链。当前允许返回 Promise 的恢复接口必须被等待，恢复失败沿用既有可观测处理，不因异步化静默丢失。

外部注入的 PackageRuntime 保持既有使用与生命周期约定；它已经发生的初始化不受本方案控制。Host 不通过读取外部实例私有字段来判断是否已准备。

这一取舍避免同时修改轻量化与故障接管语义。将来若要改变持有者默认预热范围，应单独设计恢复时机和错误发现时机，不能在本次重构中顺带切换。

### 共享全局存储不在注册阶段求值

Host 创建内置包时，不再传入 `globalStorage: this.getGlobalStorage()` 这样的立即求值参数。

在内部装配选项中增加一个同步的全局存储提供函数，例如 `globalStorageProvider: () => RuntimeStorage`。现有显式注入的 `globalStorage` 优先；其次使用 Host 提供函数；独立包最后使用自己的平台存储工厂。

- Host 提供函数复用现有 `getGlobalStorage()` 缓存，同一 Host 不为每个包重复打开全局库。
- `inMemory`、`dataDir`、`customHome`、时钟与驱动注入沿用现有解析规则，不另写路径解析器。
- 共享全局库由 Host 关闭；独立包自行创建的全局库由包关闭。
- 外部注入存储继续使用已有非接管视图或原有显式接管约定，不能因为新的资源槽位改变生命周期所有权。

提供函数必须同步，因为 `RuntimeConfig` 和 `ctx.config.get()` 的读取契约是同步的。本次不将配置读取改成 Promise，也不更改覆盖参数、包配置、全局配置、环境变量和清单默认值之间的优先级。

### 默认平台只在实际使用时创建执行组件

改造 `createNodePlatform()`，保持 `RuntimePlatform` 的公共字段与可注入能力：

- `clock` 与存储工厂可立即创建，存储工厂本身不得打开数据库。
- `process` 使用缓存访问器。显式传入 `options.process` 时直接返回，不创建未使用的 `NodeProcessDriver` 和 `ProcessManager`。
- 未传入完整进程接口时，才按既有 `processManager`、`processDriver`、默认驱动顺序装配一次。
- `modules` 使用缓存访问器，首次真正需要默认加载器时才创建 `NodeModuleLoader`。不再在平台工厂入口额外注册加载钩子。
- 不在包对象初始化、选项复制或日志序列化时展开平台对象；对象展开可能提前求值访问器。

本次只保证执行资源按需创建，不声称所有相关 JavaScript 模块均已按需导入。根入口的模块依赖图和安装依赖体积另行测量，不能把资源延迟创建等同于安装体积减少。

### 发现路径的事务与错误边界

旁观发现需要可靠清单快照，不能为了“不写盘”读取事务中的半成品。

- 检测到活跃项目修改锁时，继续返回 `PROJECT_BUSY`。
- 检测到待恢复事务时，旁观路径返回 `PROJECT_RECOVERY_REQUIRED`，不调用 `recoverPendingTransactions()`，不触发依赖安装或清单回滚。
- 默认持有者路径继续按现有机制自动恢复，再建立包图。操作者可通过原有持有者入口完成恢复，不新增修复命令。
- 显式指定的损坏清单仍报错，自动探测与链接包的失败诊断沿用现有策略，不能回退为虚构的默认包。
- 存储权限不足或不兼容数据库不阻止旁观发现；实际读取状态或历史时必须暴露原错误。默认持有者工厂仍在预热时暴露这些错误。

`withService()` 继续负责本地或远端目标解析与 `finally close()`。`info`、`list`、`describe`、规程发现使用其现有旁观选项，不在命令层复制静态发现实现。

本次不改变 `scanLinkedPackages` 的现有默认值，也不将可见包自动缩减为依赖闭包。短名消歧、全限定名、根调用可见性、Playbook 委托和跨包 `uses` 校验继续使用当前包图与策略。

### 历史、取消和事件不制造新的执行宿主

`getRun()`、`listRuns()`、历史清理与状态访问直接复用存储能力。已指定包的查询不遍历其他包；未指定包的历史查询仍访问原有范围，不能只查已经执行过的包而遗漏历史。

取消操作分支保持当前结果语义：

- 包已有执行服务时，交由该服务处理活动任务与取消信号。
- 包没有执行服务时，只读取历史记录，按现有 `already_terminal` 或 `not_found` 结果处理，不为了取消不存在的本地活动任务创建执行服务。
- 不因读取到其他进程的 `running` 记录就假定本进程拥有取消权；CLI 现有远端取消限制保留。

事件订阅在已有执行服务时沿用其事件源；没有服务时复用包或 Host 的既有事件源，不新建执行服务。Host 的 `subscribeEvents()` 不再穿透 `(runtime as any).storage`；确需确认包归属时使用现有公共运行记录查询，而不是依赖新资源槽位的私有结构。

事件序号、游标、背压和取消语义不变。不在本次增加事件落盘重放、跨进程取消或新的运行位置索引。

### 资源并发、失败与关闭

每个资源槽位只维护一个在途初始化 Promise。并发的首次调用共享结果，只有完整初始化成功后才发布实例。

- 初始化失败时释放本次新建且由本层拥有的资源，清空失败的 Promise，向调用者透传原始错误。后续显式调用可重试；不后台轮询或自动无限重试。
- 包存储已经成功而后续执行服务创建失败时，不关闭仍被状态查询使用的包存储。只回收执行初始化独自新建的资源。
- Host 初始化整体失败时仍执行整体资源回滚。清理失败记录诊断，不能覆盖最初异常。
- `close()` 首先拒绝新操作，再等待已经开始的资源准备结算，随后关闭现有执行服务、包存储和自有全局存储。
- 关闭前后都不得为了释放资源调用会新建实例的访问器。未使用对象关闭后，所有资源创建计数仍为零。
- 初始化与关闭交错时，即使初始化完成，也不能把可用实例重新发布给已关闭对象；本次创建的句柄必须释放，等待中的操作以 `SERVICE_CLOSED` 结束。
- 有活动任务时继续使用现有取消与宽限关闭机制；事件源、受管进程和调用配额治理不删除。

各方法入口统一检查关闭状态，避免延迟初始化后出现“关闭后还可以查清单或重新打开数据库”的分叉。

### Skill 说明采用摘要与按需读取

自动生成模板统一使用以下内容边界：

- 技能名称、业务描述和适用场景。
- Action 标识、原始业务描述及必要的只读或破坏性标注。
- Playbook 摘要和可读取的相对路径，保留规程优先要求。
- 一份与交付形态匹配的 `describe`、`run --json` 和 `--input-file` 调用示例。
- 一句成功读取 `data`、失败读取 `error` 的结果说明。
- 按需故障排查入口；不在每个技能正文重复展开整套安装和框架管理教程。

源码型、独立运行型与复合型都不在主说明中调用 `formatInputSchema()`、`formatOutputSchema()` 展开完整字段。完整 Schema、枚举、示例和约束继续保留在清单与 `describe` 输出中，不能因说明缩短而删掉执行校验依据。

源码型技能将详细安装与链接说明放到导出目录的 `references/actiondock-runtime.md`，主说明链接到该文件。Node 目录型技能的参考说明使用自身入口，不要求全局安装 `ad`。该文件由已有导出装配阶段写出，原有源文件和依赖闭包规划不改变；不引入模板插件或新的导出模式。

主说明优先展示免注册的当前目录执行方式；跨目录使用时才说明 `ad link`。这只是调用指引收敛，不改变路由注册功能。安全标注和业务红线不能从主说明移走，不能暗示 `destructive` 注解本身已形成强制审批机制。

复合技能的 `SKILL.custom.md` 插槽名称与相对位置保持兼容。`after-init` 对应精简后的运行参考入口，不因正文移动删除插槽。

单包导出继续尊重 `writeSkillMd()` 对已有 `SKILL.md`、显式 `skillMdPath` 和 `skipSkillMd` 的优先级。用户维护的正文不自动改写；不能为了达到长度指标覆盖已有说明。默认参考文件只在使用自动模板时生成；与项目声明资产同路径发生冲突时报告错误，不覆盖用户文件。

复合说明原位重生成仍只更新 `SKILL.md`，不增加隐式资产复制。它必须使用已有可用参考路径或保留必要的短运行说明，不能生成指向尚未物化文件的链接。

正文长度随动作和规程数量增长是正常现象。本次通过不展开 Schema 控制结构性膨胀，不截断重要业务描述，不给用户自定义正文设置未经确认的上限。

### 独立产物不再静态导入所有 Action

`generateNodeHostEntrySource()` 不再生成全部 `import action_N` 与动态定义字典。生成入口保留包清单元数据，传入产物包根目录，并让现有执行服务通过清单 `entry` 和 `NodeModuleLoader` 取得业务实现。

- 路径必须以产物目录为基准，不依赖调用者当前工作目录。
- 复用 SelectionPlan 的包内动作筛选、清单序列化与源码物化结果，不再单独复制一份 Schema 字段映射。
- 跨包外部 Action 仍不混入本包源码；依赖调用继续经 Host 和已有依赖清单路由。
- 默认导出、入口扩展名、TypeScript 类型擦除与 ESM 路径映射使用既有加载机制。
- `list`、`describe` 不导入业务模块；执行首次导入的粒度遵循现有执行服务。若当前加载器会一次加载多个本包 Action，不能把本次改动宣传为“执行时只加载一个模块”。

独立入口中的旁观发现应复用既有命令分发结果确定访问性质，不能另写一个不完整的参数解析器。执行入口继续使用持有者初始化；发现入口使用旁观初始化。版本与帮助快速返回保持原状。

监督父进程、Host 子进程和 IPC 通道不删除。减少静态导入不等于允许业务标准输出直接进入 MCP 或 CLI 机器输出。

### 公共契约收敛范围

本次不删除公开 API、状态重载、命令或分发模式。旧调用形态继续在现有归一化入口转换后委托同一实现，新的资源准备只接收已经归一化的请求。

不增加业务字段嗅探，不恢复 MCP 的执行包装 Schema，不再维护独立的轻量契约。CLI、MCP、HTTP 和 Skill 仍投影同一 Action 契约。

未来移除历史调用形态属于单独的兼容性决策，不能与按需装配混在同一次发布里。

| 调用方 | 可观察变化 | 保持不变的边界 |
| --- | --- | --- |

| CLI 状态、配置与历史 | 只准备实际需要的存储；不创建执行服务 | 状态命名空间、配置优先级、历史查询范围 |
| 默认本地公共工厂 | 存储仍在返回前就绪；执行服务延迟到执行 | 默认故障接管、存储错误暴露时机、公共返回接口 |
| HTTP 与 MCP | 继续复用默认持有者工厂；工具发现不触发业务模块导入 | 鉴权、视图隔离、取消链路和标准输出隔离 |
| 独立产物 | 发现不再触发全部 Action 顶层代码；运行首次承担模块加载 | 监督进程、IPC、文件布局约束和依赖完整性 |
| 测试框架 | 资源准备须支持 FakeClock、FakeProcessDriver 和注入存储 | 不唤起 Action 的真实系统进程、注入对象所有权 |

旁观对象的存储错误会从工厂阶段移到第一次持久化调用；调用方不能把发现成功当作存储健康检查。默认持有者对象仍保留提前发现存储错误的能力。

数据库路径、`STORAGE_SCHEMA_VERSION`、清单版本和锁文件版本均不变。本次不迁移历史数据，不修改运行记录终态、幂等键或状态编码。

## 实施顺序

### 先建立包与平台的资源边界

将包构造中的存储、执行服务与配置解析器拆成内部准备路径；保存执行委托，改造共享全局存储提供方式和默认平台访问器。Host 注册只建立身份与路由，默认持有者工厂显式完成存储准备。

主要实现边界是 `packages/core/src/package/`、`host/`、`platform/node.ts` 和既有服务工厂。此阶段必须整体衔接，不能只改构造函数却遗漏 Host 的即时全局库求值、运行记录恢复或关闭路径。

完成条件是默认持有者初始化兼容、旁观包对象资源创建为零、状态查询不创建执行服务，且所有权和关闭交错用例成立。

### 再贯通发现、历史与协议入口

将 CLI 发现命令贯通到旁观资源路径，分离旁观事务检测与持有者恢复；更新历史、取消和事件路由，删除对运行时私有存储字段的依赖。HTTP、MCP 和测试装配使用同一资源边界，不新增专用静态发现器。

主要实现边界是 `packages/cli/src/utils/target.ts`、发现命令、Host 的运行与事件端口以及 MCP 服务解析。

完成条件是实际 CLI 发现没有写盘和业务模块副作用，旁观查询不改变在途运行，默认执行和长驻服务仍完成旧记录恢复。

### 然后调整独立交付入口

使用 SelectionPlan 与已有清单序列化生成惰性业务入口，接入现有命令访问性质与模块加载器。保留父子进程输出隔离，并从产物目录验证发现和执行。

主要实现边界是 `packages/builder/src/entry-generators.ts`、既有独立命令分发与构建测试。

完成条件是独立产物发现不导入 Action、执行可以加载 TypeScript 与跨包依赖，且监督取消和机器输出仍正确。

### 最后缩短自动生成的技能说明

统一摘要边界，复用已有模板辅助函数写出运行参考，处理自定义正文、资产冲突与原位生成路径。同步更新导出示例和用户文档，明确主说明不再是完整参数清单。

主要实现边界是 `packages/builder/src/skill/templates.ts`、Skill 说明装配、源码与 Node 导出阶段。

完成条件是所有自动模板不展开完整 Schema，所有参考路径可读取，自定义说明和插槽兼容。技能参考 `describe` 的能力必须在前述资源改造通过后才能作为完整交付发布。

## 测试

以下为实现阶段必须新增或强化的案例，不表示当前已经通过。

### 验证手段

使用可计数的存储工厂、驱动工厂、模块加载器与 FakeProcessDriver，记录包库、全局库、执行服务和模块加载的创建次数。静态发现可注入“一旦创建就抛错”的资源工厂，以证明没有触及执行资源；注入平台对象本身不得预先触发访问器。

CLI 与独立产物使用独立临时家目录、未创建的数据目录和带顶层副作用的 Action 测试样本。检查 stdout、stderr、退出码、目录差异与业务模块标记，不只检查调用返回成功。Action 内受管系统命令仍使用 FakeProcessDriver，不能用真实进程替代确定性单元测试。

### 静态发现与权限

- 当前包含多个 Action，分别执行 `info`、`list`、`describe` 和规程发现：存储、执行服务、进程管理器创建及模块加载均为零，契约和规程仍完整。
- 发现命令显式指定不存在的 `--data-dir`：命令成功后该目录仍不存在，没有数据库、WAL 或数据目录锁。
- 清单可读而数据目录不可写：旁观发现成功；实际状态访问报告存储错误，默认持有者工厂仍在初始化阶段失败。
- 两个可见包存在同名动作：短名继续产生现有消歧错误，全限定名可描述；未授权的传递依赖仍不可作为根动作调用。
- 跨包 Action 未声明 `uses`：执行被拒绝，延迟装配不扩大访问权限。
- 目标工程有活跃项目锁：发现返回 `PROJECT_BUSY`；有待恢复事务：旁观发现返回 `PROJECT_RECOVERY_REQUIRED` 且不修改清单，持有者入口仍执行恢复。
- 显式工程清单损坏、链接包丢失或损坏：既有错误与诊断策略保持，不被延迟资源路径吞没。
- 使用远端 Profile 查询：结果来自远端服务，不执行本地清单替代，不打开本地包库。

### 存储、恢复与配置

- 旁观查询指定包状态或历史：只创建目标包存储，不创建全局库或执行服务；跨包历史查询覆盖全部原有查询范围。
- 旁观查询全局配置：只打开共享全局库；包配置读取按原有优先级取得正确值，密钥仍不在输出中泄露。
- 默认持有者创建多个包：在工厂返回前完成存储准备；全局库仅创建一次，未执行的包不创建执行服务。
- 数据库中有 `running` 记录：旁观状态、配置、历史与发现查询不把它改成 `interrupted`；持有者工厂按原有策略恢复真正的遗留记录。
- 存储注入实现的恢复方法返回 Promise：工厂等待恢复完成后返回，失败按规定透传或诊断，没有未处理拒绝。
- 相同幂等请求重复执行、不同输入复用请求标识：继续返回原有去重与冲突结果，初始化重试不重复登记新任务。
- 既有状态作用域、位置参数重载与选项冲突案例继续得到相同结果，不因资源槽位改造改变命名空间。

### 并发、关闭与生命周期

- 同一包并发首次读取状态：只创建一个包存储；并发首次执行：只创建一个执行服务，原有并发配额仍生效。
- 存储首次创建失败，修复后重新调用：释放失败资源，可再次初始化，不缓存永久失败或后台重试。
- 执行服务准备失败但存储已有状态读者：状态读取仍可继续，包存储没有被误关闭。
- 新建旁观对象后立即关闭：所有资源创建计数仍为零；再次调用任一端口返回 `SERVICE_CLOSED`。
- 在资源初始化等待期间关闭：初始化完成后没有活跃句柄，等待操作不会在关闭后执行 Action。
- 多个包共用全局库，或使用外部非接管存储：每个自有资源只关闭一次，外部资源不被误关；重复关闭不重新创建资源。
- 有活动任务时关闭宿主：已有取消、宽限等待、受管进程回收和终态写入行为不变。

### 运行、事件与协议

- 包未创建执行服务时查询、取消历史记录：得到现有结果，不创建执行服务；已有活动任务时取消正确传播到信号。
- 本包与跨包执行事件订阅：序号、游标、背压、finish 事件与订阅取消保持一致，不能因事件路由改变丢失完成事件。
- HTTP 与 MCP 发现后首次调用 Action：使用同一份契约，输入输出校验和错误结构与本地运行一致。
- 视图白名单与管理端口关闭：不能通过静态发现、历史查询或取消绕过权限。
- Action 意外向 stdout 写入文本：MCP 和独立机器输出仍由现有物理隔离保护，不出现协议污染。

### 独立产物与技能导出

- Action 模块顶层写入测试标记：产物 `list`、`describe` 不出现标记；执行后才出现。使用另一工作目录运行产物，结果相同。
- 产物包含 TypeScript、相对导入公共文件和外部 Action 依赖：无需重新编译即可按现有规则运行，缺失资产仍被原有构建校验拒绝。
- 源码型、Node 型、复合型自动技能使用复杂嵌套 Schema：主说明不出现完整字段展开，`describe` 仍能输出完整契约。
- 只读与破坏性标注、业务描述和 Playbook 指引：模板缩短后仍可见，规程相对路径可打开。
- 自动模板的运行参考：文件被实际导出，源码与 Node 调用方式正确；声明资产与参考路径冲突时失败且不覆盖资产。
- 已有 `SKILL.md`、显式说明路径、`skipSkillMd` 与自定义插槽：保持现有优先级，不重写用户正文。
- 复合原位重生成：只修改 `SKILL.md`，不复制资产，不新增悬空链接。

### 开销测量

在相同 Node.js 版本、相同生产依赖与相同包样本下，比较改造前后的独立进程 `ad list --json`、`ad describe --json`、状态读取、首次 `ad run` 和独立产物发现。

记录启动耗时、进程内存、数据库创建次数、模块加载次数以及生成说明的字节数。耗时和内存分别记录首次与重复调用，首次执行不能借模块缓存绕过延迟加载成本。说明尺寸比较必须区分自动模板和用户自定义正文。

本次的硬验收是资源触发边界、输出与安全语义，而不是未经测量的毫秒阈值。若首次执行明显恶化，应定位重复资源准备或模块加载，不以减少测试、取消校验或去掉输出隔离弥补。

## 发布与恢复

本轮只增加设计文档，不执行测试、构建、打包或发布。以下流程用于后续实现交付。

实现按上述依赖顺序提交，每个阶段包含对应回归断言，避免出现“包已惰性化但 Host 仍强制求值”或“技能已要求按需描述但产物发现仍导入业务代码”的中间发布状态。

发布前必须完成 `npm test`、`npm run typecheck` 与 `npm run test:pack`。打包验证使用实际安装产物检查源码、Node、MCP、HTTP 和独立入口，不以源码态通过替代分发态验证。不得因为延迟资源创建而删除原有恢复、取消、权限和跨平台用例。

发布说明明确两类行为变化：旁观发现遇待恢复事务不再自动修改工程；自动技能主说明不再列完整字段，契约由 `describe` 获取。保留所有公共命令、默认持有者行为和自定义说明优先级，不作为破坏性 API 清理发布。

GitHub Release 继续是分发触发源；预发布使用 `beta` 或 `alpha` 标签，并按目标版本对齐子包与模板互引依赖，不覆盖 `latest`。不在本地直接手工发布。

出现以下情况应暂停交付并恢复相关实现：发现调用创建数据库或导入业务模块；旁观查询修改在途运行；初始化与关闭泄漏资源；权限范围扩大；持有者恢复或独立输出隔离失效；导出说明产生不可读取的路径。

本设计不改变数据格式，回退实现不需要数据迁移。回退前停止接受新执行并等待或取消在途任务，再关闭服务后更换版本；不能让新旧执行宿主并行持有同一数据目录。

回退到旧实现后，发现操作可能重新打开数据库，这是旧行为，不是数据损坏。新模板生成的简短说明仍使用已有 `describe` 和运行语法；已经导出的技能或 Node 目录不会随框架回退自动还原，需要用对应版本重新导出或恢复先前产物。重新导出仍尊重用户已有说明，不能通过覆盖自定义 `SKILL.md` 完成回退。
