# 底层架构：安全加固与防御模型

ActionDock 2.0 在设计之初将安全性置于核心位置，构建了覆盖网络通信、凭证管理、内存防护与持久化存储的纵深防御体系。

---

## 远程网络服务安全体系

当通过 `ad serve` 启动 HTTP 微服务或通过 `ad mcp --port` 暴露网络协议服务时，执行引擎实施严格的安全防护机制：

- **非回环地址强制 Token 认证**：
  - 当服务端绑定至非本地回环地址（例如 `0.0.0.0` 或局域网、公网 IP）时，服务强制要求显式配置访问 Token，否则拒绝启动并退出。
  - 彻底防范将未受保护的服务误暴露至不可信公网导致的未授权访问与越权调用。
  - 仅在受信内部测试网络等极端特殊场景下，支持通过 `--allow-insecure-no-auth` 参数显式关闭该强制检查。
- **常数时间比较防范时序攻击**：
  - 服务端校验客户端传入的认证令牌时，支持请求头 `Authorization: Bearer <token>` 与查询参数 `?token=<token>` 两种模式。
  - 内部基于底层 `crypto.timingSafeEqual` 实现常数时间比较（`safeEqual`），确保比较耗时不受输入字符串前缀匹配长度的影响，彻底杜绝黑客利用微秒级响应时延差异推测敏感令牌的旁路时序推测攻击。
- **请求体安全限制与流式防护**：
  - 单次 HTTP 请求体默认实施 1MB 严格体积上限，防止大包拒绝服务攻击与内存溢出。
  - 实施双重流式防护：首先对请求头中的 `Content-Length` 进行预先校验，超限时直接拒绝分配内存缓冲区；对于分块传输或流式请求，在读取数据流过程中实时累计字节数，中途超出上限即刻截断流、释放锁并返回状态码 413，保障服务端内存水位稳定。
- **CORS 严格白名单机制**：
  - 默认关闭跨域资源共享，杜绝来自未经允许的前端站点的跨站请求伪造攻击。
  - 仅当启动参数中显式配置来源白名单时，服务端方才返回相应的跨域响应头。

## 敏感信息识别与脱敏展示

为防止开发者与智能体在日常交互、终端查看与调试过程中无意泄露密钥凭据，ActionDock 内置了完备的敏感数据脱敏机制：

- **敏感配置项自动判定**：
  - 显式声明判定：在配置项元数据中声明 `secret: true` 的配置，直接确认为敏感配置。
  - 正则特征启发式判定：对于未显式声明的配置，内置规则对配置键名进行通用敏感特征识别，匹配包含 PASSWORD、SECRET、TOKEN、KEY、PASS、AUTH、CREDENTIAL、PRIVATE_KEY 等命名特征的配置键。
- **命令行与界面脱敏展示**：
  - 在执行 `ad config get`、`ad config list` 或 `ad profile` 等查看命令时，所有被识别为敏感的配置值均通过脱敏处理函数统一掩码替换为 `********`，防止敏感信息在终端屏幕、终端截屏或会话录屏中泄露。
- **输入输出脱敏机制**：
  - 执行引擎在记录运行历史（Runs）与通过事件总线广播执行事件时，针对标记为敏感的配置与入参出参数据进行脱敏过滤，杜绝高权限数据库密码、外部 API Token 或私钥明文持久化至 SQLite 数据库中。

## 本地凭据与存储安全

- **物理文件系统权限防护**：
  - 本地存储多环境节点连接凭据与访问令牌的配置文件（`~/.actiondock/profiles.json`）在创建时，强制通过文件系统调用设定 `0o600` 权限模式（仅当前操作系统用户具备读取与写入权限），防止操作系统内其他非特权用户非法读取。
- **环境变量安全引用**：
  - 配置文件支持通过 `tokenEnv` 声明关联的环境变量名，在运行时动态从宿主进程环境中提取令牌，避免将明文密钥持久化写入磁盘文件。
- **多层级存储路径物理隔离**：
  - 项目开发态下的 SQLite 数据库与运行记录文件严格限定在项目根目录下的 `.actiondock/` 目录中。
  - 单文件独立可执行二进制产物的运行数据与用户全局配置严格隔离于操作系统的用户主目录，避免多项目间产生数据冲突或越权访问。

## 模式注入与原型污染防御

- **Ajv 严格模式模式校验**：
  - 所有 Action 的输入参数与项目配置在交由业务逻辑执行前，必须通过 Ajv 严格模式校验。
  - 校验器自动拦截并过滤针对 JavaScript 对象原型的恶意属性注入（如 `__proto__`、`constructor`、`prototype`），从源头消除针对 Node.js 运行时的原型链污染漏洞。
- **最小化能力上下文隔离**：
  - `ActionContext` 仅向业务 Action 暴露与其执行契约直接相关的最小化接口能力，业务逻辑无法越权获取执行引擎内部私有句柄或同进程内其他任务的上下文数据。
