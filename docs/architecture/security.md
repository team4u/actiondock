# 底层架构：安全加固与防御模型

ActionDock 2.x 在设计之初将安全性置于核心位置，构建了覆盖网络通信、凭证管理、内存防护、子进程隔离与持久化存储的纵深防御体系。

---

## 子进程标准流物理隔离与受管生命周期

Action 在执行系统命令时具有调起外部操作系统进程的能力。为了防止恶意或失控的子进程污染宿主通信通道、消耗过多宿主资源或沦为孤儿进程，ActionDock 实现了底层的物理管道隔离与受管执行生命周期管控：

### 标准流物理管道解耦

- **管道彻底隔离**：`NodeProcessExecutor` 在启动任何外部子进程时，严格配置 `stdio: ["pipe", "pipe", "pipe"]`，将子进程的标准输入、标准输出与标准错误同宿主进程物理切断。
- **杜绝宿主协议污染**：子进程无论输出任何控制字符、诊断文本或日志，均被严格捕获于子进程独立的内存流管道中，绝不可能溢出至宿主进程的标准输出。这一隔离对于 MCP STDIO 协议通信与 CLI 机器信封至关重要，彻底杜绝了下游解析崩溃。

### 受管执行生命周期与资源约束

- **输出容量严格截断**：默认对子进程输出设置 10MB 上限（`maxOutputBytes`）。实时累计管道接收的字节数，超限时立即阻断、杀死子进程并返回 `PROCESS_OUTPUT_LIMIT` 错误码，从源头防止畸形子进程耗尽宿主内存。
- **跨平台独立进程组管控**：子进程派生时启用独立进程组（在 POSIX 平台配置 `detached: true`，在 Windows 平台采用进程树管理）。当触发超时、收到取消信号或异常退出时，执行器通过 `killProcessGroup` 跨平台统一终止整个子进程树，杜绝由于主子进程脱钩导致的僵尸进程与孤儿进程在后台空转。
- **双阶段协作退出升级**：当任务超时或收到取消信号时，执行器首先发送 `SIGTERM` 信号通知子进程优雅收尾；若在设定的宽限期内未退出，强制升级发送 `SIGKILL` 信号就地回收资源。
- **租约锁孤儿追踪联动**：在数据目录租约锁（`DataDirLock`）中动态注册存活的受管子进程标识符（`registerChildPid`），即使宿主进程意外退出，后续启动的主机亦可通过 `DATA_DIR_RECOVERY_REQUIRED` 准确识别并处理残留子进程。

## 远程网络服务安全体系

当通过 `ad serve` 启动 HTTP 微服务或通过 `ad mcp serve --port <port>` 暴露网络协议服务时，执行引擎实施严格的安全防护机制：

- **非回环地址强制 Token 认证**：
  - 当服务端绑定至非本地回环地址（例如 `0.0.0.0` 或局域网、公网 IP）时，服务强制要求显式配置访问 Token，否则拒绝启动并退出。
  - 彻底防范将未受保护的服务误暴露至不可信公网导致的未授权访问与越权调用。
  - 仅在受信内部测试网络等特殊场景下，支持通过 `--allow-insecure-no-auth` 参数显式关闭该强制检查。
- **统一策略守卫与多视图权限隔离**：
  - 服务端构建了统一策略守卫体系，将原本分散在各路由与端点的鉴权逻辑、包白名单、动作白名单与管理权限统一收敛至只读的统一生效策略对象（`EffectiveServerPolicy`）。
  - 单端口多角色视图：在单个服务端口与进程中，支持通过虚拟投影视图体系为不同调用角色（如前端只读界面、自动化智能体、运维管理后台）分配独立的视图命名空间（`/views/:viewName/...`），各视图的访问令牌、包与动作白名单以及管理功能开关在策略守卫中严格隔离。
- **常数时间安全比对与全量遍历防范时序攻击**：
  - 服务端校验客户端传入的认证令牌时，默认仅支持请求头 `Authorization: Bearer <token>` 认证。查询参数 `?token=<token>` 默认被拒绝，仅在服务启动时显式传入 `--allow-query-token` 后才允许放行，防止访问令牌在反向代理、网关或浏览器历史记录中泄露。
  - 内部基于底层 `crypto.timingSafeEqual` 实现常数时间比较算法（`safeEqual`），确保字符串比较耗时不受前缀匹配长度影响。
  - 视图令牌全量恒定比对：在多视图环境中，当客户端直接请求根路径端点（`/api/v2/*` 或 `/mcp`）触发基于令牌自动识别视图时，服务端遍历所有已注册视图并严格执行常数时间安全比对，绝不采用快速退出的短路比对。无论输入令牌是否存在、前缀是否匹配或归属于哪个视图，响应耗时均保持恒定，彻底杜绝攻击者利用微秒级时延差异探测有效凭据的时序侧信道攻击。
- **视图命名空间路径规范化与防穿透防御**：
  - 针对 `/views/:viewName/...` 命名空间路由，服务端在分发前对 `:viewName` 之后的子路径实施严格的规范化处理（`posix.normalize`），自动消除连续多斜杠混淆并解析相对路径跳转，杜绝针对虚拟视图前缀的目录穿透与路径注入绕过。
  - 若请求的 `:viewName` 未在服务端注册，直接拦截并返回 HTTP 404 状态码与 `NOT_FOUND` 错误，避免非预期路由匹配。
- **请求体安全限制与流式防护**：
  - 单次 HTTP 请求体默认实施 1MB 严格体积上限，防止大包拒绝服务攻击与内存溢出。
  - 实施双重流式防护：首先对请求头中的 `Content-Length` 进行预先校验，超限时直接拒绝分配内存缓冲区；对于分块传输或流式请求，在读取数据流过程中实时累计字节数，中途超出上限即刻截断流、释放锁并返回状态码 413，保障服务端内存水位稳定。
- **传输层加密与证书安全模型**：
  - 原生 HTTPS 传输支持：服务端底层支持通过 TLS 加密通信通道，彻底消除中间人窃听与认证凭据在公网及非可信内网的明文暴露隐患。
  - 零配置自签名证书全网卡枚举：开发模式下传入 `--https` 自动在本地资产目录签发 X.509 证书。自动聚合 `localhost`、`127.0.0.1`、`::1`、系统主机名以及所有物理网卡局域网 IP 作为主题备用名称（SAN），彻底解决因网卡不匹配导致的握手失败。
  - 原子写入与严格权限防护：私钥文件生成时，严格设置 POSIX 文件系统权限为 `0o600`（仅当前用户读写），证书资产目录设置 `0o700`；生成写入采用带随机标识的临时文件配合原子的重命名操作，防止并发竞争导致私钥破损。
  - 临期自动轮换与主机自愈：本地加载缓存证书时，实时解析其过期时间戳与备用名称，当剩余有效期小于 7 天或当前绑定主机未被旧证书覆盖时，系统自动原子重新签发并更新缓存。
  - 客户端传输断言防御：客户端内置安全断言，当请求携带鉴权令牌且目标为非本地回环的明文 HTTP 服务时，默认予以阻断并抛出异常，要求启用 HTTPS 或传入显式豁免选项（`-k, --insecure` 或 `--allow-insecure-http`）。
- **CORS 严格白名单机制**：
  - 默认关闭跨域资源共享，杜绝来自未经允许的前端站点的跨站请求伪造攻击。
  - 仅当启动参数中显式配置来源白名单时，服务端方才返回相应的跨域响应头。
- **包与动作访问白名单全链路拦截防护**：
  - 支持通过全局参数（`-P, --package` 与 `-A, --action`）或虚拟视图配置（`packageAllowlist` 与 `actionAllowlist`）声明授权白名单，两份白名单取并集，`packageAllowlist` 授予整包能力，`actionAllowlist` 以全限定精确引用补充单动作授权，实现最小暴露面收敛。
  - 并集授权语义：`packageAllowlist` 数组中的包获得整包能力授权（有意覆盖该包未来新增的全部动作），`actionAllowlist` 仅接受 `packageId/actionId` 全限定精确引用，拒绝短名、通配符与空白标识，绝不宽容解析失败导致放行。某一白名单省略或为空数组只表示不增加该项授权，不会取消另一白名单的有效授权；两份白名单均无授权时，包与动作清单为空，执行请求被拒绝。`packageAllowlist: ["*"]` 为显式全量访问标记（仅支持此全局标记，不支持其他通配模式），不自动开启管理端点。
  - 默认视图部署边界：命名视图不会继承默认视图的 Token 与白名单，也不会关闭根路径。默认视图未声明授权时不暴露包与动作，执行请求被拒绝；部署授权视图时应为默认视图显式声明 `packageAllowlist: []` 与 `actionAllowlist: []` 并关闭其 MCP，或配置独立的默认管理凭据与授权（全量访问使用 `["*"]`）。
  - 调用边界：视图授权约束对外发现、直接调用与运行记录接口，不是 Action 代码的执行沙箱。已授权 Action 内部的 `ctx.actions.invoke` 仍按 `uses` 与运行时依赖规则调度，不能用 View 授权限制代替对该 Action 实现、依赖、配置读取和输出内容的信任评估。
  - 整包能力与发现可见性分离：整包授权覆盖包内全部动作；仅持有单动作授权的包在信息与发现接口仅返回最小身份元数据（标识、名称、版本、描述与已授权动作），不泄露完整动作清单、规程、配置定义与目录路径，也不能借单动作授权获取该包规程、诊断或管理能力。授权声明引用的附加包在服务启动与 MCP 服务解析时统一装载，不因仅出现在单动作引用中而缺失。发现结果只包含真实注册动作；缺少包内动作清单时补查目录，查询失败透明报错，不得回退为未经证实的授权引用。
  - 能力自省防线：全局自省（`/api/v2/info`）、包清单（`/api/v2/packages`）与动作列表（`/api/v2/actions`）由策略守卫统一过滤（`filterActionsByPolicy`、`filterPackagesByPolicy`），未授权的包与动作对客户端完全隐藏。
  - 显式调用与契约阻断：任何针对未授权包或动作的模式查询、同步执行（`run`）与异步启动（`start`），均被服务端严格阻断并抛出 HTTP 403 异常（错误码 `PACKAGE_NOT_ALLOWED` 或 `ACTION_FORBIDDEN`）；动作按解析后的实际 `packageId/actionId` 完整引用判定，未知或缺失包不放行。
  - 任务治理与审计隔离：历史运行记录列表（`runs`）、单次详情调阅、后台长任务主动取消（`cancel`）与实时事件流推送（`events`）同步受策略守卫强校验，防止越权中断或探测其他视图的长任务；运行列表逐条按实际动作引用判定授权，单动作授权目标的记录可见可查，其余动作记录不可见，且不以包集合后端预过滤导致单动作授权目标永远查询不到。
  - 管理端点门禁机制：系统配置与持久化状态端点（`/api/v2/config` 与 `/api/v2/state`）默认处于关闭状态，仅在当前生效策略显式开启 `enableManagement: true` 时放行，否则统一返回 403 `CAPABILITY_UNAVAILABLE`。`packageAllowlist: ["*"]` 不自动开启管理能力，管理与授权为独立门禁；受限授权下 `package=global` 特殊值不能绕过包级授权，未指定包时仅从持有整包授权的包中解析目标，单动作授权不推导管理权限。
  - 破坏性历史维护门禁：受限授权下，历史清理必须限定到已获整包授权的包或已授权单动作，不允许无范围清理或对仅获单动作授权的包进行整包清理。全局 `runs/clean-expired` 不支持包与动作范围，仅 `packageAllowlist: ["*"]` 显式全量授权可调用；两份白名单均无授权时不能触发任何清理操作。
  - 规程与诊断边界：规程（playbooks）与环境诊断（doctor）仅对整包授权的包开放；单动作授权不开放目标包规程与诊断，受限授权下全局 doctor 请求安全拒绝，`packageAllowlist: ["*"]` 保留全局诊断能力。
  - 模型上下文协议全方位隔离：统一根端点（`/mcp`）与各视图专属端点（`/views/:viewName/mcp`）深度绑定统一策略守卫，工具列表（`tools/list`）与调用（`tools/call`）同步受授权约束；单动作授权包的规程不得通过 MCP 资源与提示泄露；若视图配置 `enableMcp: false`，该视图 MCP 入口被彻底关闭（返回 404）。

## 敏感信息识别与脱敏展示

为防止开发者与智能体在日常交互、终端查看与调试过程中无意泄露密钥凭据，ActionDock 内置了完备的敏感数据脱敏与安全视图机制：

- 敏感配置项声明与模式判定：
  - 严格依据清单中的元数据属性进行判定：支持顶层 `secret: true` 与细粒度内嵌模式（`schema`）字段级 `secret: true`。系统不进行基于正则特征的隐式自动探测。
  - 顶层敏感保护：配置项声明顶层敏感时，整项脱敏隐藏，生效时值不返回，脱敏路径记录为根指针 `[""]`，CLI 展示为 `<hidden>`。
  - 字段级精细脱敏：若内嵌模式中的属性标记为 `secret: true`（例如数据库配置对象中的 `password` 字段），系统仅对该敏感节点脱敏，其余安全属性保留。当遇到未知字段或数据结构不符时，实施保守隐藏保护。根敏感节点不要求显式配置 `items` 或 `additionalProperties`。
  - 通配模板匹配保护：支持包含单个 `*` 的通配模板（如 `MYSQL_*`），匹配 1 个以上 `[A-Za-z0-9_.-]` 字符。匹配仲裁遵循具体精确键优先于最长字面前缀、再优先于最长字面后缀。
- 全局多包脱敏并集与继承防御：
  - 全局管理脱敏聚合所有活跃包的有效声明，取敏感保护并集。某一包针对具体键的非敏感声明绝不能撤销或削弱另一包中模板声明的敏感脱敏保护。
  - 包范围继承全局配置值时，自动享有完全同等的脱敏保护。
- 配置管理安全边界与诊断支持：
  - 运行配置的管理视图、HTTP 查询接口与 `ad config` 不提供敏感明文，也不提供明文查看参数；
  - 执行上下文原值保障：Action 运行时调用 `ctx.config.get` 始终获得完整未脱敏的业务原值；有模式时按最终生效值严格校验。
  - 脱敏只覆盖配置管理与声明自省，不会自动清理 Action 输出、日志或持久化状态。Action 作者仍须避免把原始凭据写入这些通道；Profile 凭据的查看规则不在本次变更范围内。
  - 管理容错机制：管理端调阅历史上写入的旧非法数据时，依然能够按模式定义安全脱敏输出，不会被执行期的模式校验所阻断。
- 存储中立与版本回退安全预警：
  - 底层 SQLite 配置存储保持中立，数据不加密亦不执行破坏性迁移。对外清单声明中严格清理敏感默认值与凭证约束，确保 `ad info` 与模式导出时不泄露凭据。
  - 降级安全防线：若环境计划回退降级至未支持通配模板的旧版 ActionDock，管理员必须预先为所有已持久化保存的模板实例显式补充具体键的 `secret: true` 清单声明，防范旧版本因无法识别模板而发生凭证泄露。

## 本地凭据与存储安全

- **物理文件系统权限防护**：
  - 本地存储多环境节点连接凭据与访问令牌的配置文件（`~/.actiondock/profiles.json`）在创建时，强制通过文件系统调用设定 `0o600` 权限模式（仅当前操作系统用户具备读取与写入权限），防止操作系统内其他非特权用户非法读取。
- **环境变量安全引用**：
  - 配置文件支持通过 `tokenEnv` 声明关联的环境变量名，在运行时动态从宿主进程环境中提取令牌，避免将明文密钥持久化写入磁盘文件。
- **多层级存储路径物理隔离**：
  - 包级持久化数据库与运行记录文件严格限定在各自隔离的数据存储目录中。
  - Node 目录型交付产物与全局配置严格隔离于操作系统的用户主目录，避免多项目间产生数据冲突或越权访问。

## 模式校验与原型污染防御

- **Ajv 模式校验**：
  - 所有 Action 的输入参数在交由业务逻辑执行前，必须通过 Ajv 校验器校验。校验器配置为全量错误收集（`allErrors: true`）、禁用隐式类型强转（`coerceTypes: false`）并剥离 `$id` 避免全局污染，确保严格契约匹配。
- **原型污染硬拒绝防御**：
  - 系统内置专用的原型污染深度检测（`hasDangerousKeys`）。在模式校验执行前，递归检查输入数据及其所有嵌套对象。
  - 一旦发现 `__proto__`、`constructor` 或 `prototype` 属性键名，无论模式是否允许，立即直接硬拒绝（返回失败），坚决不采用静默过滤或篡改方式，从源头彻底消除针对 Node.js 运行时的原型链污染攻击。
- **最小化能力上下文隔离**：
  - `ActionContext` 仅向业务 Action 暴露与其执行契约直接相关的最小化接口能力，业务逻辑无法越权获取执行引擎内部私有句柄或同进程内其他任务的上下文数据。
