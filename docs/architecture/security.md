# 底层架构：安全加固与防御模型

ActionDock 将安全性置于核心位置。
系统构建了纵深防御体系。
防御范围覆盖网络通信、凭证管理、内存防护、进程隔离与持久化存储。

---

## 子进程标准流物理隔离与受管生命周期

Action 运行系统命令时可调起外部操作系统进程。
为防范恶意进程污染通道或消耗资源，系统提供物理管道隔离。
系统对子进程实施受管生命周期控制：

### 标准流物理管道解耦

- 管道物理隔离：`NodeProcessExecutor` 启动外部子进程时配置 `stdio: ["pipe", "pipe", "pipe"]`。该配置物理切断子进程标准输入输出与宿主的连接。
- 杜绝宿主协议污染：子进程输出捕获于独立的内存流管道中，不会溢出至宿主标准输出。该隔离保障 MCP STDIO 通信与 CLI 机器信封稳定，避免下游解析崩溃。

### 受管运行生命周期与资源约束

- 输出容量严格截断：默认对子进程输出配置 10MB 上限（`maxOutputBytes`）。系统实时累计管道接收字节数。超限时立即阻断并终止子进程，返回 `PROCESS_OUTPUT_LIMIT` 错误码，防止耗尽宿主内存。
- 独立进程组管控：子进程派生时启用独立进程组。POSIX 平台配置 `detached: true`，Windows 平台采用进程树管理。超时、收到取消信号或错误退出时，运行器通过 `killProcessGroup` 终止整个子进程树，防止产生僵尸与孤儿进程。
- 双阶段协作退出升级：任务超时或收到取消信号时，运行器先发送 `SIGTERM` 信号通知子进程退出。若在配置的宽限期内未退出，系统升级发送 `SIGKILL` 信号强制回收资源。
- 租约锁孤儿追踪联动：数据目录租约锁 `DataDirLock` 动态注册存活子进程标识符 `registerChildPid`。宿主意外退出时，后续启动的主机通过 `DATA_DIR_RECOVERY_REQUIRED` 准确识别并清理残留子进程。

## 远程网络服务安全体系

通过 `ad serve` 启动 HTTP 服务或通过 `ad mcp serve --port <port>` 暴露服务时，引擎实施安全防护：

- 非回环地址强制 Token 认证：
  - 服务端绑定至非回环地址（如 `0.0.0.0` 或公网 IP）时，强制要求显式配置访问 Token。
  - 未配置 Token 时服务拒绝启动并退出。
  - 此策略防止未保护服务暴露于公网，避免未授权访问。
  - 测试场景支持通过 `--allow-insecure-no-auth` 参数显式关闭该强制检查。
- 统一策略守卫与多视图权限隔离：
  - 服务端构建统一策略守卫体系。鉴权逻辑、包白名单、动作白名单与管理权限统一收敛至只读生效策略对象 `EffectiveServerPolicy`。
  - 单端口多角色视图：单个服务端口支持虚拟视图体系。系统为不同角色分配独立视图命名空间（`/views/:viewName/...`）。各视图的访问令牌、白名单与管理开关在策略守卫中严格隔离。
- 常数时间安全比对与防范时序攻击：
  - 服务端检查认证令牌时，默认仅支持请求头 `Authorization: Bearer <token>` 认证。
  - 查询参数 `?token=<token>` 默认拒绝。显式传入 `--allow-query-token` 时放行，防止令牌在网关或浏览器历史泄露。
  - 内部基于 `crypto.timingSafeEqual` 实现常数时间比较算法 `safeEqual`。字符串比较耗时不受前缀匹配长度影响。
  - 视图令牌全量恒定比对：客户端请求根路径端点时，服务端基于令牌识别视图。服务端遍历所有已注册视图并运行常数时间安全比对，不采用短路比对。无论令牌是否存在或归属何处，响应耗时保持恒定，杜绝时序攻击。
- 视图命名空间路径规范化与防穿透防御：
  - 针对 `/views/:viewName/...` 路由，服务端分发前规范化 `:viewName` 后的子路径（`posix.normalize`）。
  - 处理过程自动消除多斜杠混淆并解析相对路径，杜绝目录穿透与路径注入。
  - 请求的 `:viewName` 未注册时，服务端返回 HTTP 404 与 `NOT_FOUND` 错误，避免非预期匹配。
- 请求体安全限制与流式防护：
  - 单次 HTTP 请求体默认限制为 1MB，防止大请求造成拒绝服务或内存溢出。
  - 系统实施双重流式防护。
  - 系统预先检查请求头 `Content-Length`，超限时拒绝分配缓冲区。
  - 分块传输或流式请求在读取中实时累计字节数。中途超出上限即刻截断流、释放锁并返回状态码 413，保障内存水位稳定。
- 传输层加密与证书安全模型：
  - 原生 HTTPS 传输：服务端支持通过 TLS 加密通信通道，防范中间人窃听与凭据泄露。
  - 自动枚举自签名证书：开发模式传入 `--https` 时，在本地资产目录签发 X.509 证书。系统自动聚合 `localhost`、`127.0.0.1`、`::1`、系统主机名与网卡 IP 作为主题备用名称（SAN），避免握手失败。
  - 原子写入与权限保护：私钥文件创建时配置权限 `0o600`（仅当前用户读写），证书目录配置 `0o700`。写入过程配合原子重命名操作，防止并发竞争损坏私钥。
  - 临期自动轮换：加载本地缓存证书时解析过期时间与备用名称。剩余有效期小于 7 天或当前主机未包含在证书中时，系统自动重新签发并更新缓存。
  - 客户端传输断言防御：请求携带鉴权令牌且目标为非回环明文 HTTP 时，客户端默认阻断并返回错误。调用方须启用 HTTPS 或传入豁免选项（`-k, --insecure` 或 `--allow-insecure-http`）。
- CORS 严格白名单机制：
  - 系统默认关闭跨域资源共享，防范未经允许的前端站点发起请求。
  - 仅当启动参数显式配置来源白名单时，服务端才返回跨域响应头。
- 访问白名单机制：
  - 支持通过全局参数（`-P, --package` 与 `-A, --action`）声明授权。支持通过虚拟视图配置（`packageAllowlist` 与 `actionAllowlist`）声明授权。
  - 两份白名单取并集。`packageAllowlist` 授予整包能力。`actionAllowlist` 以全限定精确引用补充单动作授权。
  - 并集授权语义：`packageAllowlist` 授予整包能力。`actionAllowlist` 仅接受 `packageId/actionId` 全限定精确引用，拒绝短名、通配符与空白标识。白名单为空表示不增加该项授权，不取消另一白名单的授权。两份白名单均无授权时清单为空，系统拒绝运行请求。`packageAllowlist: ["*"]` 为显式全量访问标记，不自动开启管理端点。
  - 默认视图部署边界：命名视图不继承默认视图的 Token 与白名单。命名视图不关闭根路径。默认视图未声明授权时不暴露包与动作，系统拒绝运行请求。部署授权视图时，应为默认视图显式配置空白名单并关闭其 MCP，或配置独立的管理凭据与授权。
  - 调用边界：视图授权约束对外发现、直接调用与运行记录接口，不是 Action 代码的运行沙箱。已授权 Action 内部调用仍按 `uses` 与依赖规则调度。视图限制不能代替对 Action 实现与输出内容的信任评估。
  - 整包能力与发现可见性分离：整包授权覆盖包内全部动作。单动作授权在发现接口仅返回最小元数据，不泄露完整动作清单、规程、配置与路径。授权声明引用的附加包在启动时统一装载。发现结果只包含真实注册动作。查询失败时透明返回错误，不回退为未证实引用。
  - 能力自省防线：全局自省（`/api/v2/info`）、包清单（`/api/v2/packages`）与动作列表（`/api/v2/actions`）由策略守卫统一过滤。未授权的包与动作对客户端完全隐藏。
  - 显式调用与契约阻断：服务端严格阻断未授权包或动作的模式查询、同步运行（`run`）与异步启动（`start`）。服务端返回 HTTP 403 错误（错误码 `PACKAGE_NOT_ALLOWED` 或 `ACTION_FORBIDDEN`）。未知或缺失包不予放行。
  - 任务治理与审计隔离：运行记录、单次详情、后台取消与事件流均受策略守卫检查。此机制防止越权中断或探测长任务。运行列表按动作引用判定授权。已授权单动作记录可见，其余动作记录不可见。
  - 管理端点门禁机制：系统配置与持久化状态端点（`/api/v2/config` 与 `/api/v2/state`）默认关闭。仅在生效策略显式开启 `enableManagement: true` 时放行，否则统一返回 403 `CAPABILITY_UNAVAILABLE`。全量访问不自动开启管理能力。未指定包时仅从整包授权中解析目标。单动作授权不推导管理权限。
  - 破坏性历史维护门禁：受限授权下，历史清理必须限定至整包授权或已授权单动作。系统禁止无范围清理，禁止对单动作授权包整包清理。全局 `runs/clean-expired` 仅全量授权可调用。白名单无授权时不可触发清理操作。
  - 规程与诊断边界：规程与环境诊断仅对整包授权的包开放。单动作授权不开放目标包规程与诊断。受限授权下系统拒绝全局 doctor 请求。`packageAllowlist: ["*"]` 保留全局诊断能力。
  - 模型上下文协议隔离：根端点（`/mcp`）与视图端点（`/views/:viewName/mcp`）绑定策略守卫。工具列表与调用同步受授权约束。单动作授权包的规程不得通过 MCP 资源与提示泄露。视图配置 `enableMcp: false` 时，该视图关闭 MCP 入口并返回 404。

## 敏感信息识别与脱敏显示

为防范在终端交互与调试过程中泄露密钥，ActionDock 内置脱敏与安全视图机制：

- 敏感配置项声明与模式判定：
  - 依据清单元数据属性判定：支持顶层 `secret: true` 与字段级 `secret: true`。系统不采用正则特征进行隐式猜测。
  - 顶层敏感保护：声明顶层敏感时，整项脱敏隐藏。脱敏路径记录为根指针 `[""]`，CLI 显示为 `<hidden>`。
  - 字段级精细脱敏：模式属性标记为 `secret: true` 时，系统仅对该敏感节点脱敏，其余安全属性保留。结构不符时实施保守隐藏。根敏感节点不要求显式配置 `items` 或 `additionalProperties`。
  - 通配模板匹配保护：支持包含单个 `*` 的通配模板（如 `MYSQL_*`），匹配一个以上字符。匹配遵循具体精确键优先于最长前缀、再优先于最长后缀。
- 全局多包脱敏并集与继承防御：
  - 全局管理脱敏聚合所有活跃包声明，取敏感保护并集。非敏感声明不能削弱模板声明的脱敏保护。
  - 包范围继承全局配置值时，自动享有同等脱敏保护。
- 配置管理安全边界与诊断支持：
  - 管理视图、HTTP 查询接口与 `ad config` 不提供敏感明文，不提供明文查看参数。
  - 运行上下文原值保障：Action 运行时调用 `ctx.config.get` 始终获得未脱敏业务原值。存在模式时按生效值严格检查。
  - 脱敏覆盖配置管理与声明自省，不自动清理 Action 输出、日志或持久化状态。Action 作者须避免将原始凭据写入这些通道。Profile 凭据查看规则保持不变。
  - 管理容错机制：管理端调阅旧非法数据时按模式安全脱敏输出，不因模式检查阻断。
- 静态加密与版本回退安全防线：
  - SQLite 配置存储按声明实施整键静态加密（AES-256-GCM）。认证附加数据绑定版本、指纹、作用域与键名。非敏感配置为明文 JSON，状态与运行记录表不加密。
  - 打开旧版（v2）库时，系统在写事务内自动加密敏感明文并升级到 v3。操作失败时回滚并报告错误。系统不将未匹配声明的配置推测为敏感配置。敏感行以密文存储，系统不擦除旧物理页明文，不自动创建备份。
  - 数据库版本防线：v3 是当前存储结构版本，新库直接以 v3 创建。旧版本程序明确拒绝打开 v3 库，回退须用自行保留的 v2 备份库恢复。
  - 对外清单声明中严格清理敏感默认值，确保 `ad info` 与模式导出时不泄露凭据。
  - 降级安全防线：回退至旧版时，管理员须为持久化存储的模板实例补充 `secret: true` 声明。此操作防范旧版本凭证泄露。

## 本地凭据与存储安全

- 物理文件系统权限保护：
  - 存储连接凭据与访问令牌的配置文件（`~/.actiondock/profiles.json`）创建时配置 `0o600` 权限。
  - 仅当前系统用户具备读写权限，防止其他用户读取。
- 环境变量安全引用：
  - 配置文件支持通过 `tokenEnv` 声明关联环境变量名。
  - 系统在运行时动态提取令牌，避免将明文密钥写入磁盘。
- 静态加密密钥管理：
  - 加密密钥优先取环境变量 `ACTIONDOCK_ENCRYPTION_KEY`（64 位十六进制）。
  - 未配置环境变量时使用密钥文件 `<dataDir>/keys/config.key`。
  - 首次需要加密时系统自动创建密钥并原子落盘。无敏感配置时不加载也不创建密钥。
  - 数据库以 `config_encryption` 记录密钥指纹。换用其他密钥时系统拒绝访问，防止混钥写入。密钥丢失后密文不可恢复，密钥文件须与备份分开保管。
- 多层级存储路径物理隔离：
  - 包级持久化数据库与运行记录文件限定在各自隔离的数据存储目录中。
  - Node 交付产物与全局配置严格隔离，避免多项目间产生数据冲突或越权访问。

## 模式检查与原型污染防御

- Ajv 模式检查：
  - Action 输入参数在业务运行前必须通过 Ajv 检查。
  - 检查器配置全量错误收集（`allErrors: true`），禁用隐式类型强转（`coerceTypes: false`），剥离 `$id` 避免全局污染。
- 原型污染硬拒绝防御：
  - 系统内置原型污染深度检测 `hasDangerousKeys`。在模式检查运行前，递归检查输入数据及其嵌套对象。
  - 发现 `__proto__`、`constructor` 或 `prototype` 属性键名时，系统立即拒绝并返回失败。系统不采用静默过滤或篡改方式，消除原型链污染攻击。
- 最小化能力上下文隔离：
  - `ActionContext` 仅向业务 Action 暴露运行契约所需的最小接口能力。
  - 业务逻辑无法越权获取引擎内部私有句柄或同进程其他任务的上下文数据。
